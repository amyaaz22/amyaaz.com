Catalyst

Getting Started with Zoho Catalyst 2.0

Amyaaz AumeerDecember 2024 · 10 min read

Catalyst started as Zoho's answer to AWS Lambda - a serverless platform for running functions without managing infrastructure. Version 2.0 expanded it into a full cloud development environment with datastores, caches, queues, AI/ML services, and DevOps tooling. For Zoho developers, it is the escape hatch for anything Deluge cannot do.

When Do You Need Catalyst?

You reach for Catalyst when you need to:

  • Use npm packages or Java libraries not available in Deluge
  • Build a standalone web application backed by Zoho data
  • Run compute-heavy processing such as PDF generation, image manipulation, or ML inference
  • Implement a custom REST API consumed by external systems
  • Process async event queues at scale

The Core Primitives

Catalyst 2.0 gives you several building blocks that work together. Functions are your serverless compute layer, running Node.js or Java code on demand or on a schedule. The Datastore is a managed relational database accessible via a REST API or the Catalyst SDK. Cache is a Redis-compatible key-value store ideal for tokens, rate-limited API responses, and configuration. Queues let you decouple processing from user-facing workflows, essential for high-volume operations.

Catalyst Datastore vs Zoho Creator Reports

A question that comes up often: why use Catalyst Datastore when Creator already stores data? The Datastore is appropriate when you need high-volume inserts, complex SQL joins across large datasets, or data that is owned by your serverless backend rather than a Creator app. If the data naturally belongs to a Creator form and is accessed through Creator pages, keep it in Creator. If you are building an independent service that happens to connect to Zoho, the Datastore is the right layer.

Connecting Back to Zoho Apps

Catalyst functions can call any Zoho API using the Catalyst SDK's built-in connector. This handles OAuth authentication automatically within the Zoho ecosystem, so you do not manage tokens manually when calling Zoho CRM, Books, or Creator APIs from your functions.

The Bigger Picture

Catalyst 2.0 positions Zoho developers to build production-grade cloud applications - not just automations. Combined with Creator for the front-end and Deluge for in-app logic, Catalyst fills the pro-code layer that previously required stepping outside the Zoho ecosystem entirely. For developers in Mauritius working with Zoho-heavy client stacks, this means you can build end-to-end solutions without leaving the platform.
